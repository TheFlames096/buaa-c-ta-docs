# 寻找最大值

## 题目背景

本题是一道交互题。本实验支持 C 和 C++ 提交。

有一个隐藏的排列，你只能向交互程序询问某个区间内「第二大的数」所在的位置。你需要利用这些回复，找出整个排列中最大的数所在的位置。

每次询问后，交互程序会立即回复。你可以根据回复决定下一次询问的区间，但总共最多只能询问 $40$ 次。

## 题目描述

交互程序预先固定一个由 $1$ 到 $n$ 构成的排列 $a$，交互过程中不会修改它。

你可以询问一个满足 $1 \le l < r \le n$ 的区间 $[l,r]$。交互程序返回该区间第二大元素在整个排列中的下标。

在不超过 $40$ 次询问后，输出满足 $a\_p=n$ 的位置 $p$。输出最终答案不计入询问次数。

## 输入

本次运行仅一组数据。

程序启动时，先读入一个整数 $n$。如果 $n=0$，请立即正常结束程序，返回 `0`；这是本 OJ 的预运行要求。评测程序会随后重新启动你的程序进行正式交互，不需要自行重启或保存上一次运行的状态。

正式交互中保证 $2 \le n \le 10^5$。隐藏排列不会直接输入你的程序。

每次合法询问后，读入一个整数 $s$，其中 $l \le s \le r$，表示第二大元素在整个排列中的下标。

如果收到 `-1` 或读到输入结束，应立即正常结束程序。`-1` 表示交互已经失败，不能继续询问。

## 输出

询问时输出一行 `? l r`，其中整数 $l,r$ 满足 $1 \le l < r \le n$，然后读取交互程序回复的下标。

确定答案后输出一行 `! p`，其中整数 $p$ 满足 $1 \le p \le n$，随后立即结束程序，不要等待确认消息，也不要继续输出。

每行命令以换行结束，不输出空行或调试信息，每行不超过 $127$ 个字符。命令中的各项用空白分隔。每次输出后必须刷新输出缓冲区；C 语言可以调用 `fflush(stdout)`。

询问次数超过 $40$、询问区间非法、协议格式错误或最终答案错误都会导致本轮失败。

## 输入样例 (1)

    2
    2

## 输出样例 (1)

    ? 1 2
    ! 1

## 输入样例 (2)

    5
    4
    5
    1
    1
    1

## 输出样例 (2)

    ? 1 5
    ? 4 5
    ? 1 3
    ? 1 2
    ? 1 2
    ! 2

## 样例解释

样例的输入和输出是一次交互记录的两个方向。只有初始的 $n$ 会主动发送，之后的每个回复都必须由对应询问触发，不能将输入样例理解成评测时预先提供的完整输入文件。

样例 1：隐藏排列为 $[2,1]$。询问整个区间后得到下标 $2$，说明第二大的数位于 $2$ 号位置，因此最大的数位于 $1$ 号位置。

样例 2：隐藏排列为 $[2,5,1,4,3]$，交互顺序如下。

| 步骤 | 选手输出 | 交互程序回复 |
| --- | --- | --- |
| 开始 | — | `5` |
| 1 | `? 1 5` | `4` |
| 2 | `? 4 5` | `5` |
| 3 | `? 1 3` | `1` |
| 4 | `? 1 2` | `1` |
| 5 | `? 1 2` | `1` |
| 结束 | `! 2` | 无，选手程序结束 |

最大值为 $5$，其位置为 $2$。重复询问是允许的，每次都会计入询问次数。样例只展示一种正确交互过程，不要求你的询问顺序与其一致。

## Hint

回复是元素在整个排列中的下标，不是元素的值，也不是相对于询问区间左端点的位置。调试输出应写入标准错误流。

C 语言的启动读取可写为：

    int n;
    if (scanf("%d", &n) != 1 || n == 0) return 0;

正式交互的时间限制为 $1000$ 毫秒，内存限制为 $65536$ KB，由交互控制程序调用 OJ 的运行监控器执行。页面显示的耗时和内存来自预运行，不代表正式交互的资源消耗。
